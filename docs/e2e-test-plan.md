# DesktopTestDriver E2E 진행 순서

**검토용 계획이다. 현재 테스트는 실행하지 않는다.** DesktopTestDriver의 연결·조작·정리만 확인한다.

1. **후보와 복귀 준비를 확정한다.** 패키지 hash, 설정, 실제 로그인 세션, 대상 앱 경로·hash, 로그 경로, 소유 프로세스와 중단·정리 수단을 기록한다. .NET은 10.x이면 되며 마이너 버전 일치를 요구하지 않는다. 입력 단계는 R1 복귀 증거가 갖춰져야 시작한다.
2. **로컬 계약 검사를 먼저 마친다.** 화면 입력 없이 상시 등록, 작업 시작·종료, 중복 요청 거부, 실패 응답, watchdog 정리 경로를 확인한다. 실패하면 원격 단계로 넘어가지 않는다.
   코딩 에이전트는 [시나리오 작성 규약](scenario-authoring.md)에 따라 사용하는 프로젝트에 시나리오/bindings/run 파일을 작성한다. 정적 검증과 모의 실행기의 결과 참조·첫 실패·정리 검사를 마친 뒤 실제 IPC의 예약/취소/단절 검사를 수행한다. 이후 단계는 고정한 JSON 시나리오를 scenario-run으로 실행하고, report.json의 앱 결과 조건·정리 영수증을 판정 근거로 사용한다. 이번 개발에서는 이 검사도 실행하지 않는다.
3. **Controller와 방화벽을 준비한다.** 조작 PC `192.168.0.61:25071`에서 후보 Controller.exe를 실행한다. 방화벽은 후보 실행 파일과 시험 PC `192.168.0.74`와 다중 머신 회차에 사용할 두 번째 시험 PC의 확정 IP만 허용한다. 두 번째 시험 PC가 준비되지 않으면 다중 머신 항목은 미실행으로 남긴다. 기존 규칙의 바이너리 경로가 후보와 일치하는지 확인한다.
4. **수동 또는 SSH로 Agent를 한 번 배포·기동한다.** 시험 PC에 파일을 직접 복사해 Agent.exe를 실행하거나, SSH 배포 어댑터와 Broker로 기동한다. 두 경로는 별도 회차에서 확인한다. 이후 작업 제어·관측·결과 수신은 Controller의 TCP 요청만 사용한다.
5. **상시 연결과 작업 수명을 확인한다.** 실제 PID·세션·hash를 대조하고 서로 다른 두 머신의 연결과 독립 작업을 확인한다. 한 머신에서 설정 폴더·machineId를 바꾼 두 번째 Agent 기동이 거부되는지도 확인한다. 각 머신에서 `시작 → inspect → 종료`를 두 작업으로 수행한다. 작업 실행부는 정리되고 같은 Agent가 재배포 없이 유지되면 통과다. 접속·작업 수명 확인은 120초 이내로 제한한다.
6. **메모장 입력을 확인한다.** Controller로 등록된 메모장을 실행하고 실제 HWND를 관측해 `aaa`를 입력한다. 본문에 실제 `aaa`가 보이는지 UIA 또는 화면으로 확인한다. 작업 소유 앱을 정리한다. 화면 점유는 60초 이내다.
7. **범용 마우스 조작을 확인한다.** 자체 MarkerWindow를 실행하고 실제 버튼 위치·ID를 관측한 뒤 마우스 이동·클릭을 요청한다. 버튼 이벤트·클릭 카운트 변화로 판정하고 작업을 정리한다. 화면 점유는 60초 이내다.
8. **장애 복귀를 별도 회차로 확인한다.** Controller 연결 단절과 작업 실행부 종료를 각각 분리해 수행한다. 입력 해제·소유 앱 정리·정상 화면 복귀·Agent 재접속·작업 자동 재실행 없음이 통과 조건이다. 각 회차 90초 이내이며 독립 watchdog과 외부 복귀 수단이 먼저 준비돼야 한다.
9. **최종 종료·정리하고 결과를 전달한다.** Controller 요청으로 작업과 Agent를 종료한다. 선택한 배포 방식에 맞춰 소유 파일·예약 작업을 제거하고 필요 없어진 전용 방화벽 규칙도 정리한다. 기존 SSH와 사용자 프로그램이 유지되는지 확인한다. 단계별 실제 시간·PASS/FAIL·증거·잔여 자원을 기록한다.

각 실행 회차는 정리·외부 복귀·결과 전달을 포함해 목표 10분, 절대 상한 15분이다. 첫 실패·준비 신호 누락·시간 초과에서 즉시 중단하고 정리한다. 같은 회차에서 재시도·코드 수정·재빌드·시나리오 추가를 하지 않는다. 연결 성공이나 명령 접수만으로 입력 기능을 통과 처리하지 않는다.

입력/장애 복귀의 사전 증거는 아직 확보되지 않았다. 위 시간 예산과 정리 경로를 사전 확인한 뒤 실행한다. 회차별 세부 판정 기준과 수집할 증거는 실행 전에 확정한다.
