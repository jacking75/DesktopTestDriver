# DesktopTestDriver 동작과 사용 흐름

DesktopTestDriver는 코딩 에이전트가 Windows PC의 창·UI·화면을 읽고 마우스·키보드를 조작할 때 사용하는 도구다. 명령과 요청 형식, 설치·설정 절차는 [코딩 에이전트용 사용 규약](agent-usage.md)을 따른다.

## 프로그램의 역할

| 프로그램 | 실행 위치 | 역할 |
|---|---|---|
| Controller.exe | 코딩 에이전트와 같은 PC | 명령을 받아 대상 Agent로 전달하고 결과·이미지를 반환한다 |
| Agent.exe | 관측하거나 조작할 각 Windows PC | 로그인된 일반 사용자 바탕화면에서 GUI 관측·입력을 수행한다 |

작업 PC 자체를 조작하려면 그 PC에도 Agent를 실행한다. 여러 PC를 사용할 때는 Controller에 연결된 machineId로 구분한다. Agent는 공개 인증서를 교환·등록한 Controller에 연결한다.

## 사용 순서

1. Controller.exe의 실제 경로, 대상 PC, 수행할 작업을 정한다.
2. `--help`와 `--status`로 사용법과 연결된 Agent를 확인한다. `--status --machine TARGET`으로 대상의 지원 기능과 데스크톱 상태를 확인한다.
3. 대상 PC에 조작용 control 세션 또는 관측 전용 observe 세션을 연다.
4. 창·요소를 조회하거나 화면을 캡처하고, 응답에서 실제 식별값을 얻는다.
5. 필요한 GUI 명령을 하나씩 요청한다. 입력 전에는 대상 창을 명시적으로 활성화한다.
6. 반환된 UI 값·이미지·로그를 읽고 다음 행동을 결정한다.
7. 작업을 마치면 필요한 앱·파일을 정리하고 세션을 닫아 도구가 누른 입력을 해제한다.

## 세션과 결과 처리

제어 세션은 같은 PC에 여러 명령을 이어 보내는 문맥이다. observe 세션은 창·UI·화면을 읽으며, 클릭·문자 입력·창 활성화·앱 실행·종료를 허용하지 않는다.

`completed`는 요청한 도구 동작이 끝났다는 뜻이다. 제품 기능의 성공 여부는 코딩 에이전트가 화면과 실제 결과를 보고 판단한다. 응답을 잃은 변경 요청은 같은 입력을 바로 반복하지 않고 `--request-status`로 원래 결과부터 조회한다.

개별 명령 프로세스가 끝나도 상주 Controller·Agent·제어 세션은 유지된다. 세션을 닫으면 도구가 소유한 입력을 해제하며, 실행한 앱의 유지·종료는 launch의 lifetime 설정을 따른다.

파일·로그·프로세스 작업에는 로컬 명령 또는 기존 SSH를 사용한다. GUI 명령과 복구 절차의 세부 사항은 [사용 규약](agent-usage.md)을 따른다.
