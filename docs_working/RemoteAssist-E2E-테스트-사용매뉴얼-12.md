# RemoteAssist E2E 테스트 사용 매뉴얼

이 문서는 **DesktopTestDriver가 완성되었다고 가정하고**, `C:\github_dev\KnockHB`의 RemoteAssist를 시험하는 사용 예시다. 실제 시험을 실행한 기록이 아니다. RemoteAssist의 동작은 아래 절차로 확인하며, 성공을 미리 가정하지 않는다.

2026-10-20 작업에서는 사용자가 RemoteAssist 실제 시험을 제외하고 가상 시뮬레이션만 요청했다. [13번 계획의 G22](GUI-사용매뉴얼-기반-상세구현계획-13.md)에 기록한 결과는 A 입력·B 관측의 도구 계약과 시험용 중계 스텁 검사다. 이 문서의 실제 승인·영상·입력 전달·즉시 종료 절차는 실행하지 않았다.

E2E는 사용자가 실제로 사용하는 연결 경로 전체를 확인하는 시험이다. 여기서는 **지원 요청 → 대상자 승인 → 화면 보기 → 원격 클릭·입력 → 대상자의 종료 → 정리**를 한 번 확인한다.

기본 호출 방식은 [간단한 GUI 테스트 매뉴얼](간단한-GUI-테스트-사용매뉴얼-11.md)과 [사용 규약](../docs/agent-usage.md)을 따른다.

## 1. 사용자가 요청한다

> KnockHB의 RemoteAssist를 두 PC에서 시험하라. 지원자 쪽에서 접속하고, 대상자인 내가 승인하면 화면이 보이는지 확인하라. Viewer를 통해 시험용 창의 버튼을 한 번 누르고 문자를 입력하라. 내가 ‘즉시 종료’를 누르면 화면과 입력이 끊기는지 확인하라. 처음 실패하면 멈추고 정리한 뒤 결과를 알려 달라.

이 예시에서 사람은 대상 PC의 지원 승인과 ‘즉시 종료’를 직접 수행한다. 코딩 에이전트는 준비·지원자 쪽 조작·관측·판정·정리를 담당한다.

## 2. 두 PC의 역할을 정한다

**작업 PC와 PC A는 동일한 머신이다.** 이 예시에서는 PC A와 PC B, 실제 PC 두 대를 사용한다.

| 위치 | 실행하는 것 | 시험에서의 역할 |
|---|---|---|
| PC A — 작업 PC이자 지원자 PC | 코딩 에이전트, Controller.exe, Agent.exe, RemoteAssist Viewer를 연 브라우저 | 두 PC의 조작을 요청하고 Viewer로 원격 입력을 보내며 결과를 비교한다 |
| PC B — 대상자 | Agent.exe, RemoteAssist 대상자 프로그램, 시험용 창 | 지원을 승인하고 실제 화면·입력을 받는다 |

PC A의 Agent는 같은 PC에서 실행 중인 Viewer 브라우저를 조작한다. PC B의 Agent는 대상 PC의 화면을 관측한다. 두 Agent는 각 PC의 로그인된 바탕화면에서 실행하며, PC A의 Controller에 연결한다.

RemoteAssist의 연결 중계 서버도 준비되어 있어야 한다. 서버와 대상자 프로그램의 설치·기동·로그 수집은 기존 SSH와 KnockHB의 준비 절차로 처리한다. GUI 조작에는 DesktopTestDriver를 사용한다.

**DesktopTestDriver의 Agent와 RemoteAssist의 대상자 프로그램은 서로 다른 프로그램이다.** 하나는 시험을 위한 도구이고, 다른 하나는 시험할 제품이다.

## 3. 시작 전에 준비한다

코딩 에이전트는 다음 항목을 먼저 확인한다.

| 준비할 것 | 확인할 내용 |
|---|---|
| 시험할 제품 | 어느 소스 버전으로 만든 RemoteAssist인지와 실행 파일을 기록한다 |
| 두 PC | 역할·접속 정보·로그인 상태·공유할 모니터를 확인한다 |
| 제품 연결 | 대상자 프로그램, Viewer 주소, 연결 중계 서버가 준비되어 있다 |
| 시험용 창 | PC B에 `RemoteAssist.InputTarget`을 실행할 수 있다 |
| 결과 보관 | PC A의 이번 시험 전용 폴더에 화면과 로그를 모을 수 있다 |
| 중단·정리 | 이번에 실행한 프로그램과 임시 설정을 식별하고 정리할 수 있다 |
| 현장 조작 | 대상자가 승인·즉시 종료·문제 발생 시 직접 조작을 할 수 있다 |

`RemoteAssist.InputTarget`은 KnockHB의 `tools\RemoteAssist.InputTarget`에 있는 시험용 프로그램이다. 창 제목은 ‘RemoteAssist 격리 입력 시험’이며 ‘시험 클릭’ 버튼과 문자 입력칸이 있다. 클릭 횟수·입력 문자·키 상태를 파일로 남기므로 실제 전달 여부를 확인할 수 있다.

시험용 창은 PC B의 로그인된 바탕화면에서 실행한다. PC B에 배치한 실행 파일로 다음 형태의 인자를 전달한다.

```text
RemoteAssist.InputTarget.exe --output C:\RemoteAssistTest\case-01 --seconds 900
```

이 예시에서는 시험용 창을 공유할 모니터에 두고 클릭 횟수 0, 입력칸 빈 상태를 확인한다. 시험용 창의 900초 자동 종료는 전체 시험의 중단·정리를 대신하지 않는다.

KnockHB의 `AGENTS.md`, `docs_working\원격제어-구현계획.md`, `docs_working\e2e-test-preparation.md`도 확인한다. 현재 단계에서 실행이 허용되는지와 준비 완료 여부를 확인하고, 부족한 것이 있으면 ‘준비 부족으로 미실행’으로 보고한다.

아래 시간은 사용 흐름을 설명하는 예시다. 실제 실행 전에는 정리와 복귀가 이 시간 안에 가능한지 확인한다.

| 구간 | 시간 기준 |
|---|---|
| 승인·화면·입력·종료 확인 | 화면을 사용하는 시험을 5분 이내로 계획한다 |
| 전체 회차 | 첫 제품 시험 동작부터 정리·정상 복귀·결과 전달까지 목표 10분, 최대 15분으로 제한한다 |
| 단계별 대기 | 예를 들어 승인 후 영상 20초, 각 입력 반영 5초, 종료 반영 10초로 정하고 시작 전에 확정한다 |

시간이 지나거나 처음 실패하면 기능 시험을 멈추고 정리한다. 같은 회차에서 수정·재빌드·재시도하지 않는다. 별도 감시가 제한 시간을 지켜 중단할 수 있는지도 시작 전에 준비한다.

## 4. DesktopTestDriver로 두 PC에 연결한다

코딩 에이전트가 PC A에서 Controller의 `--status`로 같은 PC A의 Agent와 원격 PC B의 Agent를 찾는다. 두 PC의 상태와 지원 기능을 각각 확인한다. 아래 Controller 명령은 모두 PC A에서 실행한다.

그다음 PC A에는 조작 가능한 제어 세션을, PC B에는 화면을 읽기만 하는 관측 세션을 연다. 아래 PC 이름은 실제 조회한 이름으로 바꾼다.

```powershell
& 'C:\DesktopTestDriver\Controller\Controller.exe' --session-open --machine pc-a --mode control
& 'C:\DesktopTestDriver\Controller\Controller.exe' --session-open --machine pc-b --mode observe
```

반환된 두 세션 번호를 구분해서 사용한다. PC B의 시험용 창 실행·배치는 이 관측 세션을 열기 전에 끝낸다. 준비에 조작 세션을 사용했다면 먼저 닫는다.

관측 세션은 PC B에 클릭이나 문자를 보내지 못한다. 제품 입력 시험 중에는 PC B의 시험용 창을 직접 조작하지 않는다.

이후 GUI 요청도 [첫 번째 매뉴얼의 요청 예시](간단한-GUI-테스트-사용매뉴얼-11.md)처럼 하나씩 보낸다. 클릭·입력 응답을 받지 못하면 원래 요청 번호로 결과부터 조회하며, 같은 입력을 바로 반복하지 않는다. 끝내 실행 여부를 확인할 수 없으면 시험을 멈추고 정리한다.

## 5. 접속하고 대상자가 승인한다

1. 첫 제품 시험 동작 전에 전체 제한 시간 측정을 시작한다.
2. 대상자가 PC B의 RemoteAssist에서 ‘새 지원 코드 만들기’를 누른다. 코딩 에이전트는 코드와 PIN을 이번 접속에만 사용하고 보고서·일반 로그·보관 화면에서 제외한다.
3. 코딩 에이전트가 PC A의 창 목록에서 Viewer 브라우저를 찾고 화면을 확인한다.
4. 브라우저를 활성화하고 지원자 이름, 이번 세션 코드, PIN을 입력한 뒤 ‘접속’을 누른다. 입력칸마다 클릭과 입력을 한 번씩 요청한다.
5. PC B에 승인 창이 나타났는지 확인한다. 승인 전에는 PC A에 대상 화면이 표시되지 않고 입력도 허용되지 않는지 확인한다. 내부 수신 영상 유무는 Viewer 기록도 함께 확인한다.
6. 대상자가 PC B에서 ‘화면 보기·모니터 배치 목록’과 ‘원격 제어’만 선택하고 ‘선택 권한 승인’을 누른다.
7. 코딩 에이전트가 승인 반영과 PC A의 영상 표시를 확인한다. PC B의 시험용 창이 올바른 모니터의 화면으로 보이는지 두 PC의 캡처를 비교한다.

코딩 에이전트는 대상자의 승인 버튼을 대신 누르지 않는다. 사람이 승인했다고 말한 것과 제품이 승인을 처리한 것은 각각 확인한다. 승인 후 제한 시간 안에 화면이 나타나지 않으면 실패로 기록하고 정리한다.

## 6. Viewer를 통해 클릭과 문자를 보낸다

입력이 지나가는 경로는 다음과 같다.

```text
PC A의 코딩 에이전트
  → PC A의 Controller
  → PC A의 Agent가 Viewer를 클릭·입력
  → RemoteAssist가 입력을 PC B로 전달
  → PC B의 시험용 창이 반응
```

### 버튼 클릭

1. PC B의 기록에서 시험용 버튼 클릭 횟수가 0인지 확인한다.
2. PC A의 Viewer를 새로 캡처하고 실제 이미지를 연다.
3. **Viewer에 보이는 영상 안의 ‘시험 클릭’ 버튼** 위치를 찾는다. 영상 바깥의 여백과 브라우저 도구 모음을 구분한다.
4. PC A의 브라우저를 활성화한 뒤, 방금 캡처한 이미지의 위치로 클릭 요청 한 번을 보낸다.
5. SSH로 PC B의 `C:\RemoteAssistTest\case-01\input-target.json`을 읽는다. 클릭 횟수인 `clicks`가 정확히 1인지 확인한다.

PC B에서 직접 버튼을 눌러 결과를 만들지 않는다. PC B의 Agent는 관측만 하고, 제품을 통해 들어온 입력 결과를 확인한다.

### 문자 입력

1. PC A의 Viewer를 다시 캡처하고 영상 안의 PC B 문자 입력칸을 클릭한다.
2. PC A의 Viewer 자체에 있는 ‘대상 PC에 입력할 문자’ 입력칸을 클릭하고 `REMOTE-TEST-01`을 입력한다.
3. Viewer의 ‘문자 입력’ 버튼을 누른다.
4. PC B의 기록에 남은 문자가 정확히 `REMOTE-TEST-01`인지 확인한다.
5. PC A에 표시되는 영상에도 같은 문자가 나타나는지 새 캡처를 열어 확인한다.

PC A의 입력칸에만 문자가 보이는 것은 성공 조건이 아니다. PC B의 실제 입력 결과와 PC A의 갱신된 영상까지 확인한다.

### 키 누름과 해제

1. PC A 영상 안의 PC B 입력칸을 다시 클릭한다.
2. PC A 브라우저에 F12를 한 번 눌렀다 떼는 요청을 보낸다.
3. PC B 기록에서 F12 누름과 해제가 각각 한 번 관측됐는지 확인한다. 시험용 창은 F12를 기록하고 자체 처리한다.
4. 누른 채 남은 키나 마우스 버튼이 없는지도 확인한다.

PC B를 직접 활성화하면 시험 조건이 바뀔 수 있다. 입력 중 PC B의 창을 확인할 때는 읽기와 캡처만 사용한다.

## 7. 대상자가 종료하면 실제로 끊기는지 확인한다

1. 대상자가 PC B의 RemoteAssist에서 ‘즉시 종료’를 누른다.
2. 코딩 에이전트가 PC B의 공유 중 표시가 사라졌는지 확인한다.
3. PC A에서 연결 종료가 반영되고 실시간 영상과 원격 입력이 중단됐는지 확인한다. 마지막 정지 화면이 남은 경우에는 새 영상 수신이 없는지도 기록으로 확인한다.
4. 이전 Viewer에서 입력할 수 있는 화면이 남아 있으면 같은 시험용 버튼에 클릭 한 번을 시도한다. 접속 화면으로 돌아갔다면 입력 경로가 닫힌 상태를 기록한다.
5. PC B의 클릭 횟수와 입력 문자가 바뀌지 않았고 키가 눌린 채 남지 않았는지 확인한다. 제품의 연결 종료 기록도 함께 수집한다.

화면의 ‘종료’ 문구만 보고 통과시키지 않는다. 연결 상태와 PC B의 실제 결과가 함께 맞아야 한다. 이번 기본 시험에서는 일부러 키를 누른 채 연결을 끊는 장애 시험까지 확대하지 않는다.

## 8. 성공과 실패를 정한다

| 항목 | 통과 조건 |
|---|---|
| 승인 전 차단 | 대상자 승인 전 영상 수신·원격 입력이 허용되지 않는다 |
| 승인 후 화면 | PC B의 올바른 시험용 창이 보이고 입력 후 화면도 갱신된다 |
| 마우스 | Viewer 클릭 한 번이 PC B 클릭 횟수 1로 확인된다 |
| 문자 | PC B에 정확한 문자가 한 번 들어가고 Viewer에도 반영된다 |
| 키 | F12 누름·해제가 각각 한 번 확인되고 눌린 키가 남지 않는다 |
| 대상자 종료 | 대상자 종료 후 영상·입력이 멈추고 PC B의 시험 결과가 더 바뀌지 않는다 |

Controller가 ‘요청 완료’를 반환한 것만으로 위 항목을 통과시키지 않는다. 화면과 제품 기록이 없어서 확인할 수 없는 항목은 ‘확인 불가’로 기록한다. 처음 실패한 이후의 기능 항목은 ‘미실행’으로 남긴다.

## 9. 두 PC를 정리하고 결과를 보고한다

1. 실패한 경우에도 추가 제품 입력을 멈추고 RemoteAssist 연결부터 종료한다.
2. PC A·PC B 화면, 시험용 창 기록, RemoteAssist 기록을 PC A의 이번 결과 폴더로 모은다. 코드·PIN이 들어간 화면이나 기록은 보관 대상에서 제외하거나 가린다.
3. 이번에 실행한 시험용 창·전용 브라우저·임시 제품 프로세스를 정리한다. 임시 설치·설정을 추가했다면 원래 상태로 되돌린다. 기존 설치는 사전에 정한 유지 범위를 따른다.
4. 두 DesktopTestDriver 세션을 `--session-close`로 닫고 입력 해제 결과를 확인한다. 이것만으로 RemoteAssist가 종료됐다고 판단하지 않는다.
5. 대상자에게 일반 화면과 마우스·키보드가 정상으로 돌아왔는지 확인받는다.
6. 전체 소요 시간, 항목별 결과, 첫 실패 지점, 정리·복귀 결과, 기록 위치를 보고한다.

아래는 **모든 확인이 성공한 경우의 가상 보고**다.

> RemoteAssist의 기본 연결·화면·입력·대상자 종료 시험을 통과했다. 승인 전에는 화면과 입력이 차단됐고, 승인 후 Viewer의 클릭·문자·F12 입력이 대상 PC에서 확인됐다. 대상자의 ‘즉시 종료’ 후 영상과 입력이 멈췄다. 이번 시험 자원과 제어 세션을 정리했고 대상자가 정상 복귀를 확인했다.
>
> 이번에 시험하지 않은 관리자 권한 화면, 잠금 화면, 파일 전송, 인터넷망 연결, 장시간 사용은 별도 확인이 필요하다. 이번 결과는 RemoteAssist 전체 기능의 시험 완료를 뜻하지 않는다.

이 예시에서 DesktopTestDriver의 역할은 **두 PC의 GUI를 조작하거나 읽고, 그 결과를 돌려주는 것**이다. RemoteAssist의 연결 순서·PC별 역할·대기·성공 판단·정리 순서는 코딩 에이전트가 관리한다.
